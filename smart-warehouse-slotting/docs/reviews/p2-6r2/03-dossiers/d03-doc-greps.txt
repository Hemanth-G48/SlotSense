## 5. How beam capacity is accounted for

- The greedy builds `beam_cap[(rack,bay,level)]` from `beam_max_weight_kg` and tracks `beam_load[...]` beside
  the bin, level and rack ledgers.
- `_split_quantity` receives residual **bin, beam, level and rack** capacity and returns the minimum, so a
  placement can never exceed any scope.
- Precedence matches the validator: bin → beam → level → rack. **The tolerances are not uniform, and the placer is not uniformly stricter:**
  - `CAT-01`: identical inclusive boundary in both (`d + 1e-9 >= R`).
  - `SL-01`/`SL-02`/`RK-01`: both allow `+1e-6`, so they cannot disagree.
  - `LD-01`/`VD-01`: the **validator is stricter** (no tolerance) while the placer allows `+1e-6` over. The
    placer could therefore accept a placement the validator rejects by up to 1e-6 kg/cm³ — a real but
    unreachable divergence in practice, because the placer sizes quantities in whole units (`WEIGHT_EPSILON_KG
    = 1e-9` only rounds the split arithmetic). An adversarial probe across 1,027 unit weights × 400 residual
    levels plus exact-boundary cases found no reachable overdraft.
- Verified empirically: the optimized layout has **0 `SL-02` violations** over **662 beam groups** (the repaired baseline evaluates 922, the as-supplied baseline 960 — quoting 960 for the optimized layout would attribute another layout's count to it). Phase 1 had 4 such violations.
