## 3. Optimizer root-cause analysis

The canonical starter is strong and the legacy relocation operator is inefficient:

| Metric | Legacy | Targeted |
|---|---|---|
| Feasible proposals / 600 | **270 (45.0 %)** | **426 (71.0 %)** |
| Invalid / infeasible | 330 | 174 |
| Improving proposals | **2** | **4** |
| Best improvement | **−0.0704** | **−0.8128** |
| Accepted moves | 43 | 52 |
| Final objective | **625,551.4241** | **625,551.4241** |
| Layout hash | `cafa55e8…` | `cafa55e8…` |
| Feasible / units | yes / 6,375 | yes / 6,375 |

The cause is **not** a broken objective or acceptance rule. The objective is dominated by `D` (622,468.98
of 625,551.42), and the greedy starter assigns SKUs in velocity order to the nearest feasible bins. Legacy
relocation chooses uniformly from all feasible bins, including bins occupied by another SKU, so 55 % of
proposals are rejected and only 0.33 % improve.

The targeted operator restricts relocation to **empty** feasible bins and draws from the nearest 20. It
raises feasible proposals to 71 % and improving proposals to 4, with a larger best delta, but the final
incumbent remains the starter: the improvement is too small to survive the 600-step search and is not
operationally material. No layout diversity or improvement was forced.

**Verdict:** the optimizer is near a local optimum for this instance; the remaining limitation is
neighbourhood yield, not a correctness defect. No global-optimality claim is made.
